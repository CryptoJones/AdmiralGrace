# Engine options

Every judgment call the engine makes is an option, set per run with `--option NAME VALUE` on `ag image <bin> pseudocode` and `ag image <bin> export`, and on `ag-ui`. This file is generated by `ag catalog --markdown` from the registry in `crates/ag-engine/src/options.rs`; `ag catalog --check` and `cargo test` fail when it is stale. Edit the registry, not this file.

## Symptom index

If the output shows… | Try…
--- | ---
a function whose graph runs on into the next routine's blocks after a `jmp` into it, or a `sub_…` that swallowed its neighbour | `--option branches-end-procedures yes`
a tail call to an address inside a function where the `jmp` is a loop or a shared block of the function's own | `--option branches-end-procedures no`
code in an executable section that no function in the list reaches: a stripped routine, hand-written glue after the last symbol | `--option code-sections procedures`
`sub_…` functions that are really a table, a string or padding the compiler left in `.text` | `--option code-sections mixed`
`not lifted yet: rcx is read before it is written` on an ELF built for the Microsoft convention | `--option abi win64`
`not lifted yet: rdi is read before it is written` on a PE built with a System V compiler | `--option abi sysv`
a function you know takes more arguments than its signature shows, because the tail of them is only passed on | `--option parameters convention`
`long a` in a signature where nothing reads `a` | `--option parameters last-read`
`eax`, `eax_2` and `edi` declared as locals, reading like a listing and not like C | `--option merged-register-names numbered`
`var_1` and `var_2` where you want to see which register the compiler used | `--option merged-register-names register`
`local_14` next to a listing whose offsets are decimal | `--option stack-slot-names decimal`
`local_20` next to a listing that says `[rbp-0x14]` | `--option stack-slot-names hex`
`counter` where you want the address the instruction named, to check it against the bytes | `--option pointer-loads cast`
`*(int *)0x4010` where the image has a name for the data | `--option pointer-loads named`
`b + a` and `a + b` in two functions that do the same thing | `--option operand-order canonical`
`a + b` where the listing says `add esi, edi` and you want the C to follow it | `--option operand-order instruction`
`(unsigned int)a < (unsigned int)b` cluttering every bounds check | `--option unsigned-compare bare`
`a < b` where you need to know whether a negative `a` passes | `--option unsigned-compare cast`
`not lifted yet: an indirect call` where the function pointer is a parameter | `--option indirect-calls lift`
`a(b, 1)` where the arguments of a call through a pointer cannot be trusted | `--option indirect-calls refuse`
`local_d = 0x77202c6f6c6c6568;` and the word after it, where a string was meant | `--option builtins recognize`
a `__builtin_strcpy` where the stores themselves are wanted | `--option builtins keep`
a row of `*(int *)(a + 4) = …;` stores that fill a struct field by field | `--option struct-initializers recognize`
a struct initializer where the stores themselves are wanted | `--option struct-initializers keep`
a `cmp` in the listing that the C says nothing about | `--option dead-compares keep`
`__cmp(a, b);` statements that do nothing | `--option dead-compares drop`
`return printf(a);` where the listing ends in `jmp`, and you want the functions that jump rather than call to stand out as refusals | `--option tail-calls refuse`
`not lifted yet: a tail call to printf at 0x…` on a function that ends in `jmp printf` | `--option tail-calls return`
`void f(…)` with `// void: no caller reads the result` on a function you know returns a value, whose callers in the image all discard it | `--option return-liveness presence`
`long f(void)` and `return g();` on a function whose source is `void`, the value only what the callee left in `rax` | `--option return-liveness callers`
`not lifted yet: returns a value at one ret and nothing at another` on glue such as `__do_global_dtors_aux` | `--option return-liveness callers`
`long a` on a parameter the function passes to `strlen`, or `*(int *)(a + (long)i * 4)` where an array was meant | `--option type-propagation on`
a type or an array you do not trust, where the plain integers and slots are wanted | `--option type-propagation off`
`long local_18; long local_10;` beside `f(&local_18)`, where a structure on the stack was meant | `--option auto-structs on`
a `struct struct_main_local_18` you did not write | `--option auto-structs off`
a `for` whose step is not the increment you expected, or whose init is a statement that belongs before the loop | `--option loop-form while`
`i = 0; while (i < n) { …; i = i + 1; }` where a `for` would read better | `--option loop-form for`
`goto label_…;` to a `return` a few lines up | `--option shared-tail duplicate`
the same `return` statements repeated in two arms | `--option shared-tail goto`
`rax = &completed.0;` where nothing reads `rax`, or an `if (0) { … }` block, cluttering the body | `--option dead-code drop`
a store in the listing that the C says nothing about | `--option dead-code keep`
`if (0) { // constant: &a != &a` where you want the comparison the bytes made between the parentheses | `--option constant-conditions expression`
`if (&completed.0 != &completed.0)`, a comparison that can only go one way, printed as if it could go either | `--option constant-conditions fold`
`0x64` where the source said `100` | `--option constant-style decimal`
`8` where the source said `0x8`, a mask or an offset | `--option constant-style hex`
`16777216` where `0x1000000` would be read at a glance | `--option constant-style mixed`
`(long)x` and braces where `x as i64` and `match` would read at home | `--option language rust`
`true` and `false` in an Objective-C program that says `YES` and `NO` | `--option language objc`
braces, semicolons and declarations where indentation would do | `--option language python`
bodies indented two spaces next to source indented four | `--option indent 4`
`if (c) {` next to source that puts every brace on its own line | `--option brace-style broken`
`x = (a && b) ? a : *(long *)b;` where two plain arms would read | `--option ternaries expand`
a call of six arguments running off the pane | `--option wrap 80`
`f(1, 0, 0, 1)` where which argument is which cannot be told | `--option call-hints names`

## Decode

Option | Tier | Takes | Default | What it decides
--- | --- | --- | --- | ---
`branches-end-procedures` | analysis | `no` \| `yes` | `no` | Whether a branch out of a procedure's own range ends it: a `jmp` or `jcc` to an address before the entry, or at or past the next function the image knows, is a tail call to that address rather than more of the procedure. Hand-written and shared-tail code, where routines jump into one another, reads better that way; compiled code rarely does.
`code-sections` | analysis | `mixed` \| `procedures` | `mixed` | What an executable section holds: code and data mixed, so the procedures are the functions the image names and its entry point; or procedures only, so every run of instructions no known procedure reaches starts one of its own, named `sub_` and its address, with padding — `nop`, `int3`, bytes that do not decode — passed over.

## Lift

Option | Tier | Takes | Default | What it decides
--- | --- | --- | --- | ---
`abi` | analysis | `auto` \| `sysv` \| `win64` | `auto` | The integer calling convention: read from the image's language, or System V (`rdi, rsi, rdx, rcx, r8, r9`) or Microsoft x64 (`rcx, rdx, r8, r9`) whatever the image says.
`parameters` | analysis | `last-read` \| `convention` | `last-read` | Which argument registers are parameters: the ones through the last one read, a gap declared `long`, or every register of the convention.
`merged-register-names` | rendering | `register` \| `numbered` | `register` | How a register that differs where two paths join is named once it is a variable: after the register (`eax`, `eax_2`), or by number (`var_1`, `var_2`).
`stack-slot-names` | rendering | `hex` \| `decimal` | `hex` | How a stack slot is named, by its offset from the entry stack pointer: `local_14` in hex, or `local_20` in decimal.
`pointer-loads` | rendering | `named` \| `cast` | `named` | A load or store at an address the image names as data: the data's name (`counter`), or the typed cast every other address gets (`*(int *)0x4010`).
`operand-order` | rendering | `instruction` \| `canonical` | `instruction` | The operands of `+`, `*`, `&`, `|` and `^`: in the order the instruction names them (`b + a`), or canonical, variables alphabetical and constants last (`a + b`).
`unsigned-compare` | rendering | `cast` \| `bare` | `cast` | A comparison whose condition code is unsigned (`jb`, `ja`, `jbe`, `jae`): both sides cast, `(unsigned int)a < (unsigned int)b`, or written bare, `a < b`.
`indirect-calls` | transform | `lift` \| `refuse` | `lift` | A call or a jump through a value the lift knows — a parameter, a field loaded from a struct — made as the call through that value, `a(b, 1)`, or refused as `an indirect call`. A Windows control-flow guard's dispatch — `call [__guard_dispatch_icall_fptr]` with the target in `rax`, or a `jmp` through it — is the call it guards, to that target, and its check is dropped; the target it names outright is called outright either way.
`builtins` | transform | `recognize` \| `keep` | `recognize` | The constant stores that put a string on the stack word by word, read back as one `__builtin_strcpy(&local, "text")` — or `__builtin_memcpy` where no NUL ends it — or kept as the stores they are. `rep movs` and `rep stos` read as `__builtin_memcpy` and `__builtin_memset` either way, having no other reading.
`struct-initializers` | transform | `recognize` \| `keep` | `recognize` | A run of stores through one pointer at distinct offsets — `*(int *)a = b; *(int *)(a + 4) = 2; *(long *)(a + 8) = 7;` — read as one struct initializer, `*(struct { int at_0; int at_4; long at_8; } *)a = { b, 2, 7 };`, or kept as the stores they are. Two stores at least, their values reading no memory.
`dead-compares` | transform | `drop` \| `keep` | `drop` | A `cmp` or `test` whose flags no branch reads: dropped, or kept as the statement `__cmp(a, b);` or `__test(a, b);`.
`tail-calls` | transform | `return` \| `refuse` | `return` | A `jmp` to another function with the stack as it was at entry: lifted as the call and the return it stands for, `return callee(args);` — a function that is only the jump is a thunk, printed as `// thunk for callee` — or refused, naming the callee.
`return-liveness` | analysis | `callers` \| `presence` | `callers` | Whether a function returns a value, and at what width: from use — a caller that reads `eax`/`rax` after the call decides it, and with no caller in the image only a value the function wrote itself counts, not a callee's leftover — or from presence, `rax` written on the way to a `ret`, whatever reads it.
`type-propagation` | analysis | `on` \| `off` | `on` | Whether the lift types the variables the analyst left untyped from what the code says of them (`docs/types.md`, Propagation): the prototypes of the C library's and Windows' functions it calls, strings, allocations, dereferences and unsigned uses, carried through copies, call arguments and returns across the call graph; and whether a run of stack slots indexed as an array, or whose address is passed where a prototype takes a buffer of a constant length or a known structure, is made one stack variable, `int local_38[8]`, `char local_48[64]`, `struct timeval local_18`. The analyst's types and stack variables always win. Off, the variables keep the integer of their width and the slots stay one local each.
`auto-structs` | analysis | `off` \| `on` | `off` | Whether, under `type-propagation on`, a run of stack slots whose address is taken and which no known prototype types is drafted as a structure — as `struct-from` drafts one, `struct struct_<function>_<slot>` with members `field_<hex>` — and made a stack variable of it. Off by default: the draft is a guess at a layout the analyst has not seen, and its name and members are new words in the output; `ag project … struct-from` makes one the analyst keeps.

## Structure

Option | Tier | Takes | Default | What it decides
--- | --- | --- | --- | ---
`loop-form` | transform | `for` \| `while` | `for` | A counted loop, `init; while (cond) { …; step }`: folded into `for (init; cond; step)`, or left as the `while` with its init before and its step last.
`shared-tail` | transform | `goto` \| `duplicate` | `goto` | A run of statements two paths share that neither branch dominates: reached by `goto` to a label on it, or copied into the second path when it runs straight to a `return`.

## Emit

Option | Tier | Takes | Default | What it decides
--- | --- | --- | --- | ---
`dead-code` | transform | `keep` \| `drop` | `keep` | A statement whose result nothing uses — a variable assigned and never read, or assigned again before it is read, a branch whose condition can only go one way — kept as the code made it, or dropped; a call in a dropped assignment stays, as the call it is.
`constant-conditions` | rendering | `fold` \| `expression` | `fold` | A condition that can only go one way — a relation with the same expression on both sides, `&completed.0 != &completed.0` or `rax != rax` — printed as the constant it is, `if (0) { // constant: &completed.0 != &completed.0`, with the comparison in the comment, or as the comparison itself.
`constant-style` | rendering | `mixed` \| `decimal` \| `hex` | `mixed` | How a constant is spelled: decimal below 10 and hex from 10 up, all decimal, or all hex.
`language` | rendering | `c` \| `rust` \| `objc` \| `python` | `c` | The language the pseudocode reads as: C; Rust (`fn f(a: i32) -> i64`, `x as i64`, `match`); Objective-C (C with `YES` and `NO`); or Python (`def f(a):`, blocks by indentation, `and`/`or`). The same lift, spelled each language's way.
`indent` | rendering | an integer, 1 to 8 | `2` | The spaces one level of a body is indented by.
`brace-style` | rendering | `attached` \| `broken` | `attached` | Where a control statement's opening brace goes in C and Objective-C: `attached`, at the end of the head (`if (c) {`), or `broken`, on a line of its own under it, with `else` on its own line too. Rust keeps its braces attached and Python has none.
`ternaries` | rendering | `keep` \| `expand` | `keep` | An assignment or a return of a conditional expression — `x = c ? a : b;` — kept as the one line it is, or expanded to an `if`/`else` that assigns or returns in each arm.
`wrap` | rendering | an integer, 0 to 200 | `0` | The column a statement longer than it is wrapped at, between a call's arguments, the rest indented two levels on the lines after; `0` keeps every statement on one line.
`call-hints` | rendering | `off` \| `names` | `off` | Whether a call's arguments are labelled with the callee's parameter names — `add(/* a */ 1, /* b */ 2)`, or `add(a=1, b=2)` in Python — where the callee is a function of the image whose parameters the lift has named.

## Tiers

A *transform* changes what statements there are; an *analysis* changes what the engine concludes about the code; a *rendering* changes how the same conclusion is spelled.
